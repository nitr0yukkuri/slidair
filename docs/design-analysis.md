# プレゼンテーション背景の設計分析

## 結論

このプロジェクトの価値は、天気や昼夜が変わるアニメーションではありません。プレゼンテーションに「その場の空気」を与えながら、内容の可読性と発表の構造を守ることです。

したがって、背景は次の優先順位で設計します。

1. 可読性
2. 状態の再現性と本番の安全性
3. スライド間の階層
4. 個性と世界観
5. 動きや技術的な面白さ

## 企画上の強み

### 1. 既存の個人活動と接続できる

個人サイト、記事、ポートフォリオ、発表資料が別々のデザインになるのではなく、「静かな環境」「記録」「観測」という共通する視覚言語を持てます。

### 2. 天気・時間帯は装飾ではなく状態になる

晴れ・雨・昼・夜をアイコンで説明するのではなく、色温度・明るさ・彩度・ノイズ量の変化として扱います。これにより、プレゼン中の情報を邪魔しないまま、背景に意味を持たせられます。

### 3. コード生成は再利用性が高い

画像を1枚作るのではなく、ルールから複数の背景を生成できます。表紙、区切り、本文、引用、締めを同じシステムから作ることで、資料全体の統一感を維持できます。

## 最大のリスク

### 動きが主役になる

雨粒や雲の動きを目立たせると、発表内容より背景に視線が行きます。MVPでは動きを入れず、状態が変わったときの色の遷移だけに留めるのが安全です。

### 本番環境に依存する

天気APIやネットワークに依存すると、会場で再現できない可能性があります。発表用には、URLパラメータで状態を固定するモードと、画像書き出しの経路が必須です。

### 1種類の背景では資料の階層が弱い

天気・時間帯だけで全ページを表現すると、表紙と本文が同じ重みになります。`role` を第三の状態軸として設け、光量・余白・ビネット・コントラストを制御します。

### 参考サイトの雰囲気に寄りすぎる

静かな編集的デザインを参考にするのはよい一方、特定サイトの模倣になると個人の発表資料としての理由が弱くなります。「背景は環境であり、装飾ではない」という原則を独自の軸にします。

## 状態モデル

```text
WorldState
  ├─ period: morning / day / evening / night
  ├─ weather: clear / cloudy / rain / snow / unavailable
  └─ role: cover / section / content / quote / closing
```

### period

明るさと色温度を変えます。朝は少し暖かく、昼はニュートラル、夕方は暖色と紫、夜は青みのある暗色にします。

### weather

彩度、コントラスト、光の広がり、ノイズ量を変えます。天気の記号やイラストは使用しません。

### role

情報の階層を表します。表紙は光量を少し上げ、本文は中央を静かにし、引用は余白を広く、締めは周辺を少し落とします。

## デザインの安全領域

- 中央60〜70%は文字・図表用にする
- 強い光は左右の端や四隅に寄せる
- 原色は避け、白・黒に少量の色相を混ぜる
- 背景の彩度より文字のコントラストを優先する
- 本文スライドでは背景のコントラストを表紙より下げる
- プロジェクターや会場照明で明るく見える前提で調整する

## 技術選定

### 採用

- HTML: プレビューの構造
- CSS: グラデーション、状態、レスポンシブ、モーション制御
- SVG: 控えめな粒状感
- JavaScript: 状態の取得、URL同期、プリセット操作

### 後回し

- Canvas: 大量の粒子や雨を実装する必要が出るまで不要
- WebGL: プレゼン背景には過剰で、再現性と保守性を下げやすい
- フルCMS: 背景生成のMVPの目的から外れる

JavaScriptは見た目を直接描画せず、「現在の状態を決める」役割に限定します。見た目はCSSで定義することで、色の調整と検証を容易にします。

## MVPの境界

### P0

- 16:9プレビュー
- 4つの時間帯
- 4つの天気
- 5つのスライド役割
- 手動選択
- URLで状態を固定
- オフライン動作

### P1

- 現在時刻モード
- 天気APIと正規化層
- API失敗時の固定フォールバック
- 1920×1080 PNG書き出し
- reduced motion

### P2

- PowerPoint / Google Slides向けの書き出し
- 発表用の静止画と、確認用のライブ表示の分離
- 自分のサイトや記事のOG画像との共通テーマ化

## 検証項目

- 1920×1080で中央の本文が読めるか
- 明るい会場と暗い会場で文字が沈まないか
- 表紙・本文・区切りの重要度が視覚的に分かれるか
- 15分以上表示しても動きが気にならないか
- ネットワークなしで固定状態を再現できるか
- 天気APIが失敗しても画面が崩れないか
- reduced motionでトランジションが抑制されるか
- URLを共有した相手が同じ状態を再現できるか

## 推奨する最終方針

「天気が変わる背景」を前面に出すのではなく、「発表内容を邪魔しない環境の生成器」として完成させます。表現の強さは、アニメーションではなく、低彩度の色・余白・状態の一貫性で出すのが最も相性がよいです。
